# 0.2.0 工作流程设计

## 交付内容

专业工作台包含资源表、配置检查器、日志、发布记录和 SSH 会话。简洁模式沿用选择发布包、配置访问、运行选项和发布计划。

Git 和本机目录共用项目检测与构建入口。本机完成编译，服务器接收产物。构建记录保存 Commit、配置和归档校验值。

## 操作流程

1. 连接服务器，读取服务和运行环境。
2. 选择成品包或源码，应用检测建议。
3. 设置目录、入口、端口、域名、代理和运行参数。
4. 查看计划，在任务中跟踪构建、传输和配置。
5. 读取健康检查结果，保存版本或执行恢复。

配置可导入/导出；已部署应用可复用远端当前版本更新配置。专业会话支持交互输入、尺寸同步和切页保留。

## 版式

专业模式采用 196px 导航栏、应用资源表和右侧检查器。操作区集中放置配置导入、Git 构建和发布包入口。简洁模式以概览、部署步骤和字段说明组织页面。

颜色采用 #FFFFFF、#F5F7FB、#D9E1ED、#1D2A43、#3867F4、#138A72。页面标题 24px，正文 13–14px，配置使用等宽字体。

## 验证与发布

正式回归验证 SSH、Git、识别、配置和端口。独立 Linux 实例验证完整发布，真实主机使用专用目录、端口和 Nginx 回归。

GitHub 保存源码及配套文档和测试。独立下载服务保存 Windows 安装包与校验值。源码检查在 GitHub 临时 Windows/Ubuntu 测试机运行。
