# StackPilot 0.2.0 实现与验证报告

日期：2026-11-11。仓库：[clusterstar1229/StackPilot](https://github.com/clusterstar1229/StackPilot)。

## 实现结果

0.2.0 将专业工作台、真实 SSH 终端、Git 源码构建、产物识别、配置复用和多服务交付接入现有部署流程。用户可从成品包或源码进入，经过配置、发布、健康检查和版本管理完成应用上线。

Windows 桌面负责连接与编排，本机 Docker 执行源码编译，目标 Linux 服务器运行交付产物。静态网站、原生服务、容器应用和数据库在同一工作区管理。

## 项目差异

| 参考项目 | 主要入口 | StackPilot 的工作流程 |
|---|---|---|
| [Electerm](https://github.com/electerm/electerm) | 桌面 SSH、终端和 SFTP | SSH 会话与网站、应用、数据库资源关联，并连接发布记录 |
| [1Panel](https://github.com/1Panel-dev/1Panel) | 服务器端网站、数据库和主机面板 | Windows 本地控制面，通过 SSH 管理目标服务器 |
| [Coolify](https://github.com/coollabsio/coolify) | 服务器端 Git、容器应用和数据库平台 | 成品包与源码双入口，本机编译后向服务器交付产物 |
| [Dokploy](https://github.com/Dokploy/dokploy) | 多语言、多服务、Compose 与模板 | 将镜像、相对配置和项目文件打包为一次 SSH 交付 |
| [Kamal](https://github.com/basecamp/kamal) | SSH 与容器命令行发布 | 通过向导和专业检查器编辑参数、执行发布与回滚 |
| [CapRover](https://github.com/caprover/caprover) | 服务器端容器应用、网站入口和证书 | 桌面统一管理静态产物、原生程序、容器应用和数据库 |

StackPilot 将本地桌面、成品包部署、本机源码构建、双模式界面和数据库操作组成一条连续工作流程。

## 构建方案与配置

| 方案 | 实现路径 | 项目配置 |
|---|---|---|
| 静态前端 | Node 构建，Nginx 运行输出 | 构建命令、输出目录、SPA、代理 |
| Node.js | package.json 安装/构建/启动 | start 脚本、端口、环境变量 |
| Next.js | 服务端构建和启动 | 端口、环境变量、启动命令 |
| Nuxt/Nitro | .output 识别和 server/index.mjs 启动 | 输出目录、端口 |
| Maven | Java 21、mvn package、选择 JAR | 构建目录、JVM 参数 |
| Gradle | Wrapper 或 gradle bootJar | bootJar 命令、输出目录 |
| Python | requirements、gunicorn/uvicorn | 依赖命令和 ASGI/WSGI 模块 |
| Go | Linux 编译、执行产物 | 构建入口、系统库、端口 |
| .NET | .NET 8 publish、ASP.NET 运行 | 实际程序集名称、环境变量 |
| PHP/Laravel | PHP 8.3、Apache、Composer | public 根目录、扩展、密钥和迁移 |
| 项目 Dockerfile | 按项目文件构建 | 架构、基础环境、系统依赖 |
| Compose | 多服务镜像与项目文件归档 | 服务端口、挂载文件、项目配置 |

复杂工作区通过仓库子目录、构建命令和输出路径设置入口。LFS 和子模块项目可先在本机检出完整目录，再使用文件夹入口。GPU、ARM 和系统库依赖由项目 Dockerfile 描述。

## 验证记录

认证 Git HTTP 测试核对分支 Commit 与凭据保存行为。SSH2 测试验证 Unicode 分块、PTY 输入、窗口尺寸和会话输出。Windows 与 Ubuntu 的 [Source checks](https://github.com/clusterstar1229/StackPilot/actions/runs/43017922257) 均已通过。

6. 历史版本回滚。
7. 退出码 17 的启动失败场景恢复旧服务。

10. 挂载内容一致性。

### 桌面和真实服务器

真实桌面完成 Git 拉取、构建、修改选项再次构建和产物进入发布向导。桌面检查覆盖首次空工作区、模式布局、窗口和渲染执行环境。

Ubuntu 24.04.2、894MB RAM 主机完成独立目录、本机端口和独立 Nginx 的轻量发布回归。验证了 PTY、静态站点、SPA、配置复用、历史回滚和失败恢复；受检服务进程、重启记录、业务文件及 Nginx 配置校验值与基线一致。业务入口保持 HTTP 303。

安装包经过 NSIS 载荷解包、真实主程序启动、版本与内容检查，公网完整下载的 SHA-256 与本地文件一致。
