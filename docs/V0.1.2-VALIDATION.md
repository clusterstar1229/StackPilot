# 栈桥 StackPilot 0.1.2

Windows 本地 SSH 运维桌面应用。安装 exe 后双击运行，Electron 内置 Node.js 执行层，无须用户另开服务，也不需要在远端部署管理面板。

## 本次更新

- SSH 端口继续保持可选、默认留空；需要自定义映射端口时填写。
- 增加独立 Java Home、逐行 JVM 参数、CPU 上限和 systemd 资源切片配置。
- 服务器高级设置支持工具目录、独立 Docker Unix Socket 与客户端配置目录；仅作用于本应用 SSH 会话。
- 数据库安装增加内存、CPU、进程数限制和就绪检查；拒绝复用已有容器、配置目录和数据卷。
- MongoDB 低内存安装通过无网络的临时容器与 SSH 私有套接字初始化账号，减少服务器上 mongosh 的启动开销。此模式需要 root SSH 和普通 rootful Docker。
- 修复 SSH 数据库转发通道释放，40 次连续查询后连接数保持为 1；修复 MySQL SHA-2 密码账号通过远端 Unix Socket 认证与恢复的兼容性。
- Redis 新实例支持持久化只读 ACL；PostgreSQL 读写授权包含当前与后续序列；备份恢复处理原账号授权与 MySQL GTID 的兼容问题。
- 容器历史回滚的健康检查覆盖连接重置等启动阶段错误；数据库升级保留资源限制和 Alpine 镜像变体。
- 保留源码与安装包，移除验证脚本、发布样包、截图、测试数据、运行环境与测试镜像。

## 使用

1. 安装 `StackPilot-Setup-0.1.2-x64.exe`，从桌面快捷方式启动。
2. 在“服务器”填写名称、IP、用户名和凭据。普通 SSH 可不填端口；自定义连接填写平台给定端口。
3. 首次连接核验主机指纹。凭据可选择由 Windows DPAPI 加密保存，或只在本次运行期间保留。
4. 点击“部署应用”，选择构建产物，配置目录、端口、域名、运行方式，检查计划后发布。
5. 在“任务与审计”查看每一步；在应用的版本入口中回滚，在日志和监控中排查问题。

首次启动为真实空工作区，左下角可开启独立演示。演示数据始终标明，不连接真实服务器。安装包未进行商业代码签名。

## 保护已有项目

发布到新主机时可使用“现有系统 Nginx”模式。若主机已有业务且只需验证，选择“临时隔离实例”，并关闭“安装缺失的基础运行环境”：

- 隔离实例只监听 `127.0.0.1`，使用应用目录中的独立配置与日志。
- 此模式按需启动，不配置服务器开机启动或公网证书；点击站点链接通过 SSH 隧道预览。
- 应用运行账号可在高级设置中指定为已有非 root 账号。不存在的账号会按部署计划创建；不更改已有账号设置。
- 使用全新应用名、专用根目录和未占用端口。未知来源的目录和 Nginx 配置不覆盖。
- 多实例使用连续端口，蓝绿备用组使用基础端口 +100。

普通模式下，网站端口与后端运行端口应分开，例如 Nginx 80、应用 8080。原生应用需要 root 或 sudo 免密管理权限，并以非 root 服务账号运行。

## 运行包与限制

- 静态包展开后需要 `index.html`；识别一层 `dist` 等外包目录。拒绝越界路径、链接、特殊文件与 SUID/SGID 文件，限制展开体积和文件数。
- 原生 WAR 仅适用于可执行 WAR；普通 WAR 模板为 Docker/Tomcat 10（Jakarta），旧 javax 项目需兼容镜像。
- Node.js 有 lockfile 时使用 `npm ci --omit=dev`。Python 使用独立 venv。Java 可选择 8/11/17/21/25，实际安装取决于目标系统软件源。
- Go／二进制需与 Linux 及其 CPU 架构匹配。Windows exe 不能直接作为 Linux 运行包。
- .NET 模板默认 .NET 8。Compose 需要目标已有 Docker Compose；禁用提权、host 网络及宿主目录挂载，端口显式绑定本机。
- 数据库安装需要已有 Docker。复制组模板位于同一主机，不提供整机故障容灾；PostgreSQL 复制模板适配 13—17 的目录布局。
- 自动升级只处理本系统创建、数据卷布局符合模板的独立容器，要求精确且更高的同主版本号，先备份并复制数据卷，保留旧实例。
- 恢复只创建新目标，不覆盖已有库；通用恢复入口支持关系型单库 SQL／SQL.GZ 和 SQLite。MongoDB／Redis 二进制恢复当前需使用引擎管理工具，不包含在通用恢复入口。PostgreSQL 恢复不带原账号的所有权与授权；MongoDB 在线归档不保证跨集合的同一时间点快照。

## 操作策略与数据

服务器重启／关机、删除数据库／数据卷、任意 Shell、破坏性 SQL 不提供操作入口。中危操作使用 5 分钟内有效的一次性计划，连接或目标变化后必须重新预览。查询工作台只读，数据修改通过独立确认入口。

上传程序、依赖安装脚本和 Compose 命令属于用户信任的可执行内容；运维策略不等于恶意程序沙箱。

工作区保存在 `%APPDATA%\StackPilot\workspace`。凭据与环境变量使用 Windows 系统加密。不要跨 Windows 账户复制加密凭据文件。更新环境变量时保留界面的加密占位符可复用原值。

也可使用 `StackPilot.exe --user-data-dir=C:\自选绝对路径` 指定独立工作区；未指定时使用默认位置。

默认每 15 秒采样，最多保留 7 天／每台 40320 个样本。桌面关闭后停止采样与本地通知；正式部署的服务器服务、cron 备份和证书续期继续运行。

应用归档位于 `/var/backups/stackpilot/apps`，数据库备份位于 `/var/backups/stackpilot/databases`。归档不包含外部数据库或容器命名卷，建议通过文件管理下载副本。

自动 DNS 需要服务商授权，备案号不能替代解析权限。自动证书使用 HTTP-01，需要正确解析和可达的 80 端口；泛域名证书可上传配置。

## 源码构建

开发环境需要 Windows x64、Node.js 22.12+ 和 npm。在源码目录执行：

```powershell
npm ci
npm run dev
```

开发启动会自动运行 Vite 与 Electron。最终用户只需安装 exe。

```powershell
npm run build
npm run dist
```

`npm run dist` 在上一级“安装包”目录生成 NSIS 安装文件。源码交付不包含 node_modules 和开发构建目录，需先安装依赖再构建。

目录：`src` 为界面，`electron` 为执行层，`shared` 为模型和校验，`scripts` 为开发／构建脚本，`build` 为应用图标，`docs` 为设计及参考记录。

开源参考与接口依据见 [REFERENCES.md](docs/REFERENCES.md)。本项目独立编写，业务源码为 MIT；依赖保留各自许可证，生产依赖记录见 `THIRD_PARTY_NOTICES.json`。
