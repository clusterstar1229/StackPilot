# 0.2.0 需求与设计

已确认：专业模式提供完整 SSH 终端；Git 业务源码在本机 Docker 构建后上传；StackPilot 自身源码准备开源，安装包通过服务器独立下载服务分发。GitHub 推送等待用户后续授权。原服务器仅轻量隔离回归，安全组变更先确认。

## 可验收增量

1. 切换专业模式时，应用展示资源表格、配置与版本检查器、源码构建入口和交互式终端；简洁模式继续保留引导式发布。
2. 终端支持多会话、PTY、交互输入、Ctrl+C、窗口尺寸同步及页面切换后恢复；不逐条确认命令。
3. 本地目录及常用发布包能识别运行类型与建议入口，无法确定时显示依据并允许覆盖。
4. Git HTTP(S) 仓库可在无需本机 Git/语言 SDK 的条件下克隆，通过本机 Docker 构建镜像、导出并经 SSH 上传到目标机运行；记录 commit 与构建配置。
5. 部署配置可以导入导出，专业模式可编辑配置，部署前仍检查实际目标与必要字段。
6. 报告逐项区分模板支持、实际验证、需自行配置与未覆盖范围，不宣称覆盖所有应用或全球首创。
7. 下载服务与原业务分目录、分端口；服务器不保存 StackPilot 源码与构建环境。

## 视觉方案

沿用已获认可的浅色界面：纸白 #FFFFFF、工作底色 #F5F7FB、边线 #D9E1ED、正文 #1D2A43、操作蓝 #3867F4、健康绿 #138A72。中文 Microsoft YaHei UI，正文 13–14px；数据和配置 Cascadia Code，页面标题 24px。

简洁模式以步骤和解释为主；专业模式以应用资源表、右侧检查器和会话终端为主。模式不是权限角色，切换不会更换数据或结束远端任务。

```
专业：服务器 / 环境选择       导入配置   Git构建   上传发布
应用资源表                   配置 / 日志 / 发布记录检查器
交互终端入口                 实时任务和构建输出
```

复核：保留现有品牌与字体，不以换配色制造模式差异；专业视图的每一个区域均连接实际对象和操作，避免装饰性 IDE 空面板。

## 基础安全与验证

保留 SSH 主机身份、凭据加密、IPC 来源检查和避免覆盖未知项目的基本保护。完整终端按操作者命令执行；图形界面继续不提供服务器关机、删库、删卷按钮。Compose 和构建脚本按用户信任的可执行配置处理。

在本机隔离 Docker 环境测试主要流程，原服务器只回归 SSH/终端/轻量发布；下载服务发布前检查原服务状态，开放安全组前询问具体规则。
